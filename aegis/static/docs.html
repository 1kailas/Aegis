Aegis AI Documentation

Autonomous Infrastructure Engineering Control Plane, Hardware-Aware Model Recommender, and One-Click Cloud Native Deployer.

Aegis AI is an enterprise-grade infrastructure monitoring and engineering control plane designed for modern compute clusters, containerized workloads (Docker & Kubernetes), and on-premise AI model serving. It continuously observes host telemetry, protects hardware with deterministic safety guardians, automatically triages and diagnoses failures using local and cloud AI models, delegates repository repairs to Devin, and validates fixes before PR submission.

The Central Architectural Invariant
Aegis monitors and orchestrates. Deterministic controllers enforce safety. AI investigates and engineers fixes. Independent verification determines whether the fix actually worked.
🛡️
Dual-Plane Safety
Critical thermal, PSI, and resource limits are hardcoded deterministic algorithms that operate 100% offline without cloud LLM dependencies.
🌐
Distributed Cluster Mesh
Connect any Linux client device in seconds simply by supplying the server IP address. Zero manual package compilation required.
🧠
AI Model Hub & Deployer
Profiles host VRAM, RAM, and CPU cores to categorize models into Best, Marginal, and Worst fit tiers, deployable with 1-click to Docker or K8s.
⚡
Live Benchmarking & Optimizer
Empirically benchmarks Time-To-First-Token (TTFT) and decoding tokens/sec while proactively evicting idle models to avoid OOM kills.

5-Minute Quickstart

Get an Aegis AI control plane and worker agent up and running in under five minutes.

Step 1: Start the Aegis Server

The server runs the centralized dashboard, SQLite WAL database, and self-healing orchestrator:

bash 
# 1. Clone the repository
git clone https://github.com/1kailas/Aegis.git
cd Aegis

# 2. Setup virtual environment & install
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

# 3. Launch the Aegis Control Plane server
aegis-server --host 0.0.0.0 --port 8000

Once started, the following services are available immediately:

  • Web Dashboard: http://localhost:8000
  • Interactive Documentation: http://localhost:8000/documentation
  • OpenAPI Swagger UI: http://localhost:8000/api/docs
  • Prometheus Scrape Endpoint: http://localhost:8000/metrics

Step 2: Inspect Status with the Developer CLI

In another terminal, use the unified aegis CLI tool:

bash 
aegis status

Installation Options

Option A: Automated One-Line Linux Installer

Recommended for production hosts and server nodes. Automatically installs virtual environment, links binaries to /usr/local/bin, and provisions systemd background services:

bash 
./scripts/install.sh --role all

Option B: Docker Compose

Deploy the control plane and a co-located monitoring agent in isolated containers:

bash 
docker-compose up -d

1. Deterministic Safety Plane

Operates 100% locally and offline. Monitors Linux Pressure Stall Information (PSI), CPU thermal throttling states, memory exhaustion, and NVMe health. It uses deterministic thresholds, hysteresis curves, and hold times to prevent flapping. Prohibited commands (e.g. rm -rf /, bash pipes, reading secrets) are hardcoded and mathematically rejected.

2. AI Diagnostic & Engineering Plane

When an incident occurs, telemetry and redacted logs are evaluated by a 3-tier fallback engine. If the incident stems from a code or configuration bug, Aegis delegates the task to Devin as its intelligent repair engineer, providing sanitized logs, failure traces, and reproduction commands.

3. Independent Verification Plane

Never trusts patches or claims of success blindly. Fixes are tested in ephemeral local git sandboxes, and post-remediation health is verified with independent live probes before an incident is marked resolved.

Deterministic Guardians

Aegis includes two primary deterministic guardians that protect physical hardware from degradation or sudden hardware death:

ThermalGuardian

  • Configurable Thresholds: Warning (°C), Critical (°C), and Recovery (°C).
  • Rate-of-Rise Alerting: Detects sudden thermal spikes (°C/sec) before the absolute threshold is hit.
  • Hysteresis & Cooldown: Enforces recovery hold periods (default: 60s) to prevent remediation flapping.
  • Hardware-Aware Limits: Respects physical sensor capabilities without inventing fake numbers.

ResourceGuardian

  • Memory Pressure: Monitors Available RAM, Swap usage, and Linux Memory PSI.
  • Disk Space & I/O: Monitors root and data mount utilization and IO latency.
  • CPU Saturation: Monitors CPU load averages and CPU PSI stalls.

3-Tier AI Diagnosis Engine

To eliminate cloud dependency and protect operational continuity, Aegis uses a hierarchical 3-tier diagnosis engine:

Tier Engine Availability Role
Tier 1 Local Ollama (qwen2.5:1.5b) Local / On-Prem Instant zero-latency diagnosis without internet or external API dependencies.
Tier 2 Cloud Google Gemini Internet Reachable Deep root-cause synthesis for complex multi-subsystem cascading failures. Enforces hourly rate limiting.
Tier 3 Deterministic Rule Engine 100% Offline Deterministic expert rules (OOM detection, thermal throttling, crash loops) guaranteeing diagnosis continuity.

Devin Repair Protocol

Aegis integrates with Devin as its designated autonomous software and infrastructure repair engineer:

  1. Structured RepairTask: Formats failure traces, incident metadata, and explicit reproduction criteria into a clean specification.
  2. Ephemeral Sandbox Validation: Clones the target repository into an isolated workspace (repair-workspaces/<task_id>).
  3. Strict Patch Scope Check: Automatically rejects patches that attempt to modify .env files, modify GitHub Actions workflows, or traverse parent directories (../).
  4. Evidence-Backed GitHub PR: Submits pull requests using gh CLI containing complete test execution logs, exit codes, and verification checklists.

The 10 Inviolable Safety Principles

Aegis operates according to ten non-negotiable operational invariants:

  1. No AI Control Over Safety Mechanisms: Thermal and physical limits are deterministic code. AI models cannot alter physical protection thresholds.
  2. No Arbitrary Shell Execution: AI cannot execute arbitrary bash commands on the host. Actions are strictly bound to an allowlist.
  3. No Unverified Success Claims: An incident is never marked resolved simply because a PR was opened or patch compiled. Live probe verification is required.
  4. Zero Secret Leakage: Credentials, API tokens, and .env variables are scrubbed from telemetry, diagnosis prompts, and PR bodies.
  5. No Destructive Operations Without Approval: Destructive commands (e.g. dropping tables, stopping essential host daemons) require explicit human operator confirmation.
  6. No Cloud Dependency for Routine Monitoring: Whole-system telemetry and guardians function 100% offline.
  7. Zero Fabrication: Missing or unsupported sensors report UNAVAILABLE. No fake telemetry is ever generated.
  8. Explainable and Traceable: Every decision and transition is written to an immutable SQLite audit log.
  9. Graceful Degradation: If Docker, Kubernetes, or Ollama goes down, Aegis logs the state and continues monitoring remaining subsystems.
  10. Modular and Testable: High test coverage across all subsystems.

Distributed Cluster Mesh

Aegis extends from a single-machine monitor into a multi-node distributed cluster mesh.

Zero Configuration Joining
Any client machine running standard Linux with Python 3 can join the cluster mesh simply by specifying the Aegis server IP. No pip packages or git installations are required.

Connecting Any Client Machine

Run the one-liner on the client machine, pointing to the server's IP address (e.g. 192.168.1.50):

bash 
# Instant Zero-Install Run (Runs standalone in user space)
curl -sSL http://<SERVER_IP>:8000/agent.py | python3 - <SERVER_IP>

For a persistent background daemon managed by systemd:

bash 
# Automated systemd service installation
curl -sSL http://<SERVER_IP>:8000/install.sh | bash -s <SERVER_IP>

AI Model Optimization Hub & Deployer (v3.0 & v3.1)

Aegis features a hardware-aware AI model intelligence engine that inspects host compute hardware and ranks open-source models based on physical feasibility.

Deterministic Fit Tiers

Fit Tier Badge Hardware Condition Performance Profile
OPTIMAL OPTIMAL 100% of weights fit in GPU VRAM with headroom for 32k KV cache. Peak tokens/sec throughput, zero CPU layer offload, instant TTFT.
GOOD GOOD Weights fit in VRAM with headroom for standard 4k-8k context. High tokens/sec throughput with minimal latency impact.
MARGINAL MARGINAL Exceeds VRAM; requires partial layer spilling into system RAM. 4x–10x latency penalty due to PCIe bus bandwidth bottlenecks.
INCOMPATIBLE INCOMPATIBLE Exceeds combined VRAM and RAM capacity. High risk of CUDA Out-Of-Memory (OOM) kills or system crashes.

Supported Model Catalog

The catalog includes top-performing open-source weights across 4 task domains:

  • Coding: Qwen 2.5 Coder (1.5B, 7B, 14B, 32B)
  • Reasoning: DeepSeek R1 Distill (8B, 14B, 32B, 70B)
  • Fast Chat & Ops: Llama 3.3 (8B, 70B), Mistral v0.3 (7B), Phi-4 (14B)
  • Embeddings: Nomic Embed Text v1.5 (8192-token context)

1-Click Cloud Native Deployment

Deploy any recommended AI model without writing manual Docker commands or Kubernetes manifests.

1-Click Docker Deployment

Launches an optimized container with GPU passthrough (--gpus all) and persistent model cache:

bash 
aegis models deploy qwen2.5-coder:7b --runtime docker --port 11434

1-Click Kubernetes Provisioning

Generates production-grade Kubernetes YAML with resource requests/limits, readiness probes, and ClusterIP Services:

bash 
aegis models deploy deepseek-r1:8b --runtime k8s --port 11434

Real-Time Model Benchmarking (v3.1)

Empirically benchmark deployed or simulated models to measure true inference performance:

  • TTFT (Time-To-First-Token): Exact duration from prompt dispatch to the first emitted token chunk (ms).
  • Decoding Throughput: Sustained token generation rate (tokens/second).
  • Prompt Evaluation Rate: Prompt processing speed (tokens/second).
bash 
aegis models benchmark qwen2.5-coder:7b

Dynamic VRAM Memory Optimizer (v3.1)

Reclaim GPU VRAM and system memory during heavy traffic or thermal stress. Scans active inference runtimes and unloads idle models with keep_alive: 0:

bash 
aegis models optimize

Closed-Loop Self-Healing

Aegis executes autonomous reconciliation cycles over active incidents:

  1. Detection: An anomaly is detected by guardians or workload probes (State: DETECTED).
  2. Triage & Diagnosis: 3-tier diagnosis hypothesizes root cause (State: INVESTIGATING).
  3. Remediation: If allowlisted in policy_autonomous mode, safe remediations are executed (State: CONTAINED).
  4. Devin Delegation: Code or config defects are routed to Devin (State: REPAIRING).
  5. Independent Verification: Live probes verify workload recovery, transitioning incident directly to RECOVERY_VERIFIED.
Emergency Stop
At any time, an operator can trigger the global emergency stop kill-switch to immediately freeze all autonomous actions: aegis estop on

Progressive Delivery & Canary Rollbacks

Aegis monitors canary rollouts step-by-step. If error budgets or latency SLAs are breached during any step, Aegis triggers an immediate closed-loop automated rollback:

bash 
# Inspect active canary rollouts
aegis canary list

# Manually abort and rollback a canary
aegis canary rollback <rollout_id>

ADMIN Full control: key generation, mode changes, emergency stop, deployment deletion.
OPERATOR Workload deployment, canary advancement, manual remediation triggers.

Production Operations & Troubleshooting FAQ

Q: What happens if the host has no NVIDIA GPU?

Aegis automatically detects GPU absence and marks GPU metrics as UNAVAILABLE. The Model Recommender automatically switches to CPU RAM mode, recommending lightweight models (e.g. Qwen 2.5 Coder 1.5B or Nomic Embed) and warning that larger models are incompatible, without fabricating false telemetry.

Q: Can Aegis run without internet connectivity?

Yes. Routine telemetry collection, deterministic Thermal/Resource guardians, local Docker orchestration, Tier-1/Tier-3 incident diagnosis, and local model deployment function 100% offline.

Q: How do I rotate or revoke an API key?

Generate a new token using aegis keys create --name new-key and delete the old key using the REST API DELETE /api/security/keys/{key_id}.
